# Plan

*No active plan.*

`plan.md` is generated by `/uc-to-plan <ucNN>` from a use case spec in
`documentation/use-cases/`, and consumed by `/plan-to-task` to produce `tasks.md`.

There are no use case specs yet — `documentation/use-cases/` currently holds only
`use-case.spec.template.md`. That is deliberate: specs are written for what is **touched**,
not back-filled across the existing service (`sdd.playbook.md` § 9).

## Getting started

1. `/spec-create <TICKET-KEY>` — turn a Jira/Confluence ticket into one or more use case
   specs. It halts on any of the seventeen ADR triggers rather than guessing.
2. `/uc-to-plan uc01` — turn a spec into a plan here.
3. `/plan-to-task` — break the plan into a phased checkbox list in `tasks.md`.
4. `/execute-task 1.1` — implement one block, TDD-first.

Or, for a spec that is already complete: `/loop-uc UC01` runs the outer loop until its
Definition of Done is met.

## Before the first increment

Read `CLAUDE.md` for the authority order, then the four always-read documents it lists.
