# Domain Specification – MasterLeasingContract

## Purpose

`MasterLeasingContract` is the **Leasing-Rahmenvertrag (LRV)**: the framework
agreement between a Lessor (*Leasinggeber*) and an Employer (*Arbeitgeber*) under
which individual bike leases are issued.

It enforces the contract lifecycle, the versioning of its commercial terms, and
the constraints those terms impose on everything issued beneath it.


## 1. Aggregate Root

Name:
`MasterLeasingContract`

Description:
Represents one framework leasing agreement, identified by a
`MasterLeasingContractId` and carrying exactly one *current* `MlcConfiguration`.

Consistency boundary:

**Inside**: the contract and its current `MlcConfiguration`. The configuration is a
domain entity within this aggregate, not an aggregate of its own, because amending
it is not an independent act — it produces a new version, the contract must point
at exactly one current version, and whether the amendment is permitted depends on
the contract's status. Those three facts must be true together or not at all, which
is the definition of one consistency boundary (`modelling.definition.md`, Aggregate).

**Referenced by id, outside the boundary**:
- `parentMasterLeasingContractId` — the base contract, when this one is an
  affiliated/supplementary contract for a company in the same corporate group. A
  reference between two aggregates of the same type, carried as an id.
- `employerId`, `lessorId` — records in external systems (ADR 0005 category 3).
- Individual leasing contracts issued under this one. This aggregate does not know
  them, does not count them, and holds no collection of them. That is what makes
  the credit limit a *policy* checked at issue time by the other context rather
  than an invariant here (`modelling.definition.md`, Policies vs Invariants).

**Not modelled**: `MLC_CONFIGURATION.dynamic_fields`, and the version *history* of
configurations. Only the current version is held; superseded versions are a
read-side concern and there is no use case for them yet
(`documentation/notes.md`).


## 2. Invariants (Always-Valid)

- **I-01**: `partnerNumber` is non-blank → `PartnerNumber` throws
  `InvalidMasterLeasingContractException`
- **I-02**: a contract is never its own parent → `register` throws
  `InvalidMasterLeasingContractException`
- **I-03**: the initial configuration is version 1 → `register` throws
  `InvalidMasterLeasingContractException`
- **I-04**: activation is permitted only from `DRAFT` → `activate` throws
  `InvalidMasterLeasingContractStateException`
- **I-05**: an amendment's version is exactly the current version plus one →
  `amendConfiguration` throws `InvalidConfigurationVersionException`
- **I-06**: an amendment is permitted only from `DRAFT` or `ACTIVE` →
  `amendConfiguration` throws `InvalidMasterLeasingContractStateException`
- **I-07**: cancellation is permitted only from `ACTIVE` → `cancel` throws
  `InvalidMasterLeasingContractStateException`
- **I-08**: `cancelledDate` is not before `activationDate` → `cancel` throws
  `InvalidMasterLeasingContractException`
- **I-09**: `priceRange.min <= priceRange.max`, both in the same currency and both
  non-negative → `PriceRange` throws `InvalidMasterLeasingContractException`
- **I-10**: `creditLimit` is non-negative → `CreditLimit` throws
  `InvalidMasterLeasingContractException`
- **I-11**: `eligibleEmployees` is non-negative → `EligibleEmployees` throws
  `InvalidMasterLeasingContractException`
- **I-12**: `noticePeriod` is between 1 and 36 months inclusive → `NoticePeriod`
  throws `InvalidMasterLeasingContractException`
- **I-13**: `returnQuota` is a percentage between 0 and 100 inclusive →
  `ReturnQuota` throws `InvalidMasterLeasingContractException`
- **I-14**: `cancellationReason` is non-blank and at most 400 characters →
  `CancellationReason` throws `InvalidMasterLeasingContractException`

Violations MUST result in an exception.

**I-08 is the one worth arguing about.** A contract cancelled before it was
activated is not merely odd, it makes the notice period uncomputable and makes any
lease issued in between unattributable to a live agreement. It is checked against
the stored `activationDate`, which is why that date is aggregate state and not
event payload (`modelling.definition.md`, What an aggregate stores).


## 2a. Value Objects

### MasterLeasingContractId
- Wraps `UUID`. Immutable, equality by value.
- **Category 1** (`modelling.definition.md` § Identity): owned by this context, so a
  Value Object living here. Where `individualleasing` references it, it is a plain
  `String`.
- Generated by the application layer before aggregate creation.

### PartnerNumber
- Wraps `String` — the *Partnernummer*, the join key between Odoo and Radar.
- Invariant: non-blank (I-01).
- **Category 4**: an external system's identifier referenced by this context only.
  A Value Object here rather than a `String`, because there is no peer context whose
  independence a `String` would protect (ADR 0005).

### CancellationReason
- Wraps `String` — the *Kündigungsgrund*, the ground on which the Lessor terminated.
- Invariants: non-blank and at most **`MAX_LENGTH = 400`** characters (I-14).
- Length is checked on the raw value, before any trimming, so trailing whitespace
  cannot carry the text past the ceiling and then vanish.
- **Declared in this context, not shared.** `individualleasing` has a type of the
  same name meaning something different — an employee's reason for ending one lease.
  Sharing the type would force one context's vocabulary onto the other (ADR 0003).

### ConfigurationVersion
- Wraps `Int`. Invariant: `>= 1`.

### CreditLimit
- Wraps `Money`. Invariant: non-negative (I-10).
- The maximum credit exposure permitted on this contract. Enforced against the
  *sum of leases* nowhere in this aggregate — see § 1, and UC05.

### PriceRange
- Two `Money` values, `min` and `max`.
- Invariants: same currency, both non-negative, `min <= max` (I-09).
- The band of bike prices this contract's conditions permit leasing.

### EligibleEmployees
- Wraps `Int` — *JobRad-Berechtigte*. Invariant: `>= 0` (I-11).

### NoticePeriod
- Wraps `Int` months — *Kündigungsfrist*. Invariant: `1..36` (I-12).

### ReturnQuota
- Wraps `Percentage` — *Rückgabekontingent*, the share of active leases per year
  that may be dissolved without penalty. Invariant: `0..100` (I-13).

### Enums
- `MasterLeasingContractStatus`: `DRAFT`, `ACTIVE`, `CANCELLED`, `ENDED`
- `ContractType`: `SALARY_SACRIFICE`, `EMPLOYER_FUNDED`, `MIXED` — the commercial
  model the contract runs under
- `SalesChannel`: `DIRECT`, `PARTNER`, `PORTAL`
- `InheritanceMode`: `LIVE_LINKED`, `COPIED_ONCE` — whether terms inherited by a
  lease stay linked or are copied once. **Only `COPIED_ONCE` is implemented**; see
  `documentation/notes.md`.

Each is an enum rather than a value object because the set is closed, there is
nothing to validate, and no behaviour attaches to a member.

### MlcConfiguration (domain entity, inside the aggregate)

Holds the versioned commercial terms:

| Property | Type | Notes |
|----------|------|-------|
| `version` | `ConfigurationVersion` | increments by exactly one per amendment (I-05) |
| `inheritanceMode` | `InheritanceMode` | |
| `contractType` | `ContractType` | |
| `salesChannel` | `SalesChannel` | |
| `creditLimit` | `CreditLimit` | |
| `priceRange` | `PriceRange` | |
| `eligibleEmployees` | `EligibleEmployees` | |
| `jointLiability` | `Boolean` | *gesamtschuldnerische Haftung* (KUV/gsH) |
| `returnQuota` | `ReturnQuota` | |
| `noticePeriod` | `NoticePeriod` | |

It is an entity rather than a value object because it has identity across versions:
version 2 of a contract's configuration is the same configuration, amended, not a
different value.


## 3. State Model

Possible states:
- `DRAFT`
- `ACTIVE`
- `CANCELLED`
- `ENDED`

Allowed transitions:
- `DRAFT → ACTIVE` — `activate` (UC02)
- `ACTIVE → CANCELLED` — `cancel` (UC04)

Illegal transitions:
- `DRAFT → CANCELLED` — a contract that was never active has nothing to terminate;
  it is abandoned, not cancelled, and abandonment is not modelled
- `CANCELLED → any`
- `ENDED → any`
- `ACTIVE → ACTIVE` — a second `activate` throws rather than no-opping, unlike the
  individual-contract side. Activation here is a deliberate operator action through
  a mutation, not a fan-out that may be re-delivered, so a repeat is a mistake the
  caller should be told about

`ENDED` is reachable from no function today. It is declared because the data model
has it — a contract that ran to its natural end rather than being cancelled — and
the transition needs a time-based trigger this system does not yet have. Recorded
as an open item in § 7 rather than removed, because removing it would lose the
distinction between "ended" and "cancelled" that `cancellation_reason` depends on.


## 4. Behavior

Public functions:

- `register(...)` — static factory
- `reconstitute(...)` — static factory, persistence only
- `activate(activationDate: LocalDate, now: Instant)`
- `amendConfiguration(newConfiguration: MlcConfiguration, now: Instant)`
- `cancel(cancelledDate: LocalDate, reason: CancellationReason, now: Instant)`
- `pullDomainEvents(): List<DomainEvent>`

Plus read-only accessors: `contractId`, `employerId`, `lessorId`, `partnerNumber`,
`parentMasterLeasingContractId`, `configuration`, `status`, `activationDate`,
`cancelledDate`, `cancellationReason`.

**Mutable (`var`, `private set`) properties**: `configuration`, `status`,
`activationDate`, `cancelledDate`, `cancellationReason` — five. Every one of them
must be written by `MasterLeasingContractRepository.update`
(`ports/master-leasing-contract-repository.outport.spec.md`). Adding a sixth
without extending `update` and its round-trip assertion means the change does not
survive a write.

Absence is expressed as `T?`, never `Optional`
(`coding-style.definition.md` § 1.4). `activationDate` is null before activation;
`cancelledDate` and `cancellationReason` are null unless cancelled. There are no
setters.

### register(contractId, employerId, lessorId, partnerNumber, parentMasterLeasingContractId, configuration, now)

Creates a new contract in `DRAFT`.

Preconditions:
- `parentMasterLeasingContractId != contractId` → else
  `InvalidMasterLeasingContractException` (I-02)
- `configuration.version == 1` → else `InvalidMasterLeasingContractException` (I-03)

Postconditions:
- `status = DRAFT`
- `activationDate`, `cancelledDate`, `cancellationReason` all null
- the supplied configuration is the current one

Emitted events:
- `MasterLeasingContractRegistered(contractId, employerId, lessorId, occurredAt)`

Note: a cycle longer than one hop — A's parent is B, B's parent is A — is **not**
detected. It spans aggregates and cannot be checked from inside one
(`documentation/notes.md`). I-02 catches only the self-reference.

### reconstitute(contractId, employerId, lessorId, partnerNumber, parentMasterLeasingContractId, configuration, status, activationDate, cancelledDate, cancellationReason)

Rebuilds a persisted contract.

Preconditions: none by design — the data was valid when written
(`modelling.definition.md` § Rehydration Rule). Structural validity is still
required: a row that cannot produce a valid value object fails loudly rather than
producing a half-built aggregate.

Postconditions:
- the aggregate reflects stored state exactly, in any status
- no pending domain events

Emitted events: none. **Persistence mapper only** — `MasterLeasingContractMapper`
is its sole caller. It must stay public because the mapper lives in another
package, so visibility cannot express the restriction;
`ClassRoleRulesTest.reconstitute_isCalledOnlyByPersistenceMappers` enforces it and
fails the build if anything outside `..outbound.persistence..` calls it (ADR 0007).

### activate(activationDate, now)

Transitions `DRAFT → ACTIVE`.

Preconditions:
- `status == DRAFT` → else `InvalidMasterLeasingContractStateException` (I-04)

Postconditions:
- `status = ACTIVE`
- `activationDate` stored — it bounds every lease issued under this contract
  (UC05 rejects a `termStart` before it), which is the observer that makes it state
  rather than event payload

Emitted events:
- `MasterLeasingContractActivated(contractId, activationDate, activatedAt)` —
  **in `shared.domain.event`**, because `individualleasing` consumes it (UC06)

### amendConfiguration(newConfiguration, now)

Replaces the current configuration with the next version — the LRV's terms changed.

Preconditions:
- `status in (DRAFT, ACTIVE)` → else `InvalidMasterLeasingContractStateException`
  (I-06)
- `newConfiguration.version == configuration.version + 1` → else
  `InvalidConfigurationVersionException` (I-05)

Postconditions:
- `configuration` replaced

Emitted events:
- `MlcConfigurationAmended(contractId, newVersion, occurredAt)` — context-local

Notes:
- The version check is `== current + 1` rather than `> current` deliberately. A gap
  in the version sequence would make the history unreconstructible and would hide a
  lost update: two concurrent amendments both computing "current + 1" is a conflict
  the strict check turns into a failure rather than into a silently dropped version.
  There is no optimistic locking, so this check is the only thing that notices —
  see § 7, Open.
- Amending does **not** propagate to leases already issued, because only
  `COPIED_ONCE` inheritance is implemented (`documentation/notes.md`).

### cancel(cancelledDate, reason, now)

Transitions `ACTIVE → CANCELLED`, recording when and on what ground.

Preconditions:
- `status == ACTIVE` → else `InvalidMasterLeasingContractStateException` (I-07)
- `cancelledDate >= activationDate` → else
  `InvalidMasterLeasingContractException` (I-08)
- `reason` non-null — cancelling a framework agreement without a stated ground is
  not permitted, unlike an individual lease where a reason is optional

Postconditions:
- `status = CANCELLED`
- `cancelledDate` and `cancellationReason` stored

Emitted events:
- `MasterLeasingContractCancelled(contractId, cancelledDate, reason, occurredAt)` —
  **context-local, deliberately not in `shared`**. UC04 propagates cancellation to
  the leases by calling `individualleasing`'s inport inside one transaction, not by
  publishing (`architecture.definition.md` § 10). Promoting this event to the shared
  kernel for symmetry with `MasterLeasingContractActivated` would put a type there
  that no consumer needs

Notes:
- **A second cancellation throws.** It is not an idempotent no-op. This aggregate is
  cancelled once, by an operator, through a mutation; a repeat is a mistake and the
  client should be told (a `CONFLICT`). The individual-contract side is different
  and the asymmetry is deliberate — see that aggregate's § 4.

### pullDomainEvents()

Returns an immutable snapshot of recorded events and clears the internal list. A
second call returns empty. This is the drain every driver uses:

```kotlin
contract.pullDomainEvents().forEach(domainEventPublisher::publish)
```


## 5. Domain Events

All implement `shared.domain.event.DomainEvent`. All are immutable `data class`es.
Published post-commit via `DomainEventPublisher` (ADR 0002).

| Event | Trigger | Payload | Package |
|-------|---------|---------|---------|
| `MasterLeasingContractRegistered` | `register` | `contractId`, `employerId`, `lessorId`, `occurredAt` | `masterleasing.core.domain.masterleasingcontract.event` |
| `MasterLeasingContractActivated` | `activate` | `masterLeasingContractId` (`String`), `activationDate`, `activatedAt` | **`shared.domain.event`** |
| `MlcConfigurationAmended` | `amendConfiguration` | `contractId`, `newVersion`, `occurredAt` | `masterleasing.core.domain.masterleasingcontract.event` |
| `MasterLeasingContractCancelled` | `cancel` | `contractId`, `cancelledDate`, `reason`, `occurredAt` | `masterleasing.core.domain.masterleasingcontract.event` |

`MasterLeasingContractActivated` carries the contract id as a plain `String`, not as
`MasterLeasingContractId`. It lives in `shared.domain.event`, which
`architecture.definition.md` § 9 forbids from depending on any bounded context — so
the typed id cannot appear there, and the consuming context would treat it as opaque
anyway (ADR 0005 category 2).

Payloads are **not** uniform. Only `MasterLeasingContractRegistered` carries the
employer and lessor; the others carry what their consumers need and nothing more
(`modelling.definition.md`, What an aggregate stores).


## 6. Failure Scenarios

| Scenario | Exception | Thrown by |
|----------|-----------|-----------|
| Contract is its own parent | `InvalidMasterLeasingContractException` | `register` |
| Initial configuration version is not 1 | `InvalidMasterLeasingContractException` | `register` |
| Activate when not `DRAFT` | `InvalidMasterLeasingContractStateException` | `activate` |
| Amend when `CANCELLED` or `ENDED` | `InvalidMasterLeasingContractStateException` | `amendConfiguration` |
| Amendment version is not current + 1 | `InvalidConfigurationVersionException` | `amendConfiguration` |
| Cancel when not `ACTIVE` (including a second cancel) | `InvalidMasterLeasingContractStateException` | `cancel` |
| Cancellation date before activation date | `InvalidMasterLeasingContractException` | `cancel` |
| Blank or over-long cancellation reason | `InvalidMasterLeasingContractException` | `CancellationReason` |
| Price range inverted, mixed-currency or negative | `InvalidMasterLeasingContractException` | `PriceRange` |
| Negative credit limit or eligible headcount | `InvalidMasterLeasingContractException` | `CreditLimit`, `EligibleEmployees` |
| Notice period outside 1..36 | `InvalidMasterLeasingContractException` | `NoticePeriod` |
| Return quota outside 0..100 | `InvalidMasterLeasingContractException` | `ReturnQuota` |
| Blank partner number | `InvalidMasterLeasingContractException` | `PartnerNumber` |
| Contract not found | `MasterLeasingContractNotFoundException` | the driver, not the aggregate |

Value-object construction rejects its own invalid input. Note that `Money` and
`Percentage` live in `shared.domain` and therefore throw
`IllegalArgumentException` rather than a domain exception — the shared-kernel
exemption in `coding-style.definition.md` § 6.2, mapped to `BAD_REQUEST` by the
exception resolver.


## 7. Test Requirements

Expressed as checkable items naming the test that satisfies each.

### Covered
- [ ] Creation invariants I-01 to I-03 — `MasterLeasingContractTest.register_*`
- [ ] Value object invariants I-09 to I-14 — `PriceRangeTest`, `CreditLimitTest`,
      `NoticePeriodTest`, `ReturnQuotaTest`, `CancellationReasonTest`,
      `PartnerNumberTest`, `EligibleEmployeesTest`
- [ ] `DRAFT → ACTIVE` transition and its guard (I-04) —
      `MasterLeasingContractTest.activate_*`
- [ ] Configuration amendment, version rule (I-05) and state guard (I-06) —
      `MasterLeasingContractTest.amendConfiguration_*`
- [ ] `ACTIVE → CANCELLED` transition, guards I-07 and I-08, and the
      non-idempotence of a second cancel — `MasterLeasingContractTest.cancel_*`
- [ ] Event emission and drain semantics — `MasterLeasingContractTest.pullDomainEvents_*`
- [ ] Persistence round-trip of every mutable property, at the declared scale —
      `MasterLeasingContractPersistenceAdapterIT`
- [ ] No setters, no framework import, no `Instant.now()` in the domain — enforced
      mechanically by `DependencyRulesTest` and `ClassRoleRulesTest` (ADR 0007)

### Open
- [ ] **`ENDED` is declared and reachable from no function.** It needs a time-based
      trigger (a contract reaching its natural end) that this system has no scheduler
      for. Closing it means either a use case with a clock-driven trigger — which is
      `@Scheduled`, an ADR under `sdd.playbook.md` § 6 item 6 — or removing the state
      and losing the distinction from `CANCELLED`.
- [ ] **No optimistic locking.** Two concurrent amendments can both read version *n*
      and both compute *n+1*; I-05 makes the second fail only if the first already
      committed, which under read-committed is not guaranteed. A `@Version` column is
      the fix and is a persistence-strategy change, hence an ADR
      (`sdd.playbook.md` § 6 item 4).
- [ ] **Configuration history is not retained.** Only the current version is stored,
      so `MlcConfigurationAmended` is the only record that version *n* existed. An
      audit view would need a history table.
